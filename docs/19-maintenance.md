## 19.1 การสำรองข้อมูล (Backup)

ข้อมูลทั้งหมดของระบบ (ผู้ใช้งาน, ประวัติแชท, สถิติ, ความรู้ AI) อยู่ใน volume ชื่อ `mysql_data` ควรสำรองข้อมูลเป็นประจำด้วยวิธีใดวิธีหนึ่งต่อไปนี้:

**วิธีที่ 1 — ผ่าน phpMyAdmin (ง่ายที่สุด)**

1. เข้า `http://<เซิร์ฟเวอร์>:8096`
2. เลือกฐานข้อมูล `faonex` ทางเมนูซ้าย
3. ไปที่แท็บ **Export** → เลือกรูปแบบ SQL → กด **Go** เพื่อดาวน์โหลดไฟล์สำรอง

**วิธีที่ 2 — ผ่านคำสั่ง (สำหรับสำรองอัตโนมัติ)**

```bash
docker compose exec mysql mariadb-dump -u root -p faonex > backup-$(date +%Y%m%d).sql
```

### กู้คืนข้อมูลจากไฟล์สำรอง

```bash
docker compose exec -T mysql mariadb -u root -p faonex < backup-20260101.sql
```

{: .important }
> ทดสอบขั้นตอนกู้คืนข้อมูลไว้ล่วงหน้าก่อนเกิดเหตุจริงเสมอ อย่ารอจนกว่าจะเกิดปัญหาแล้วค่อยมาลองทำครั้งแรก

## 19.2 ปัญหาที่พบบ่อยและวิธีแก้

### ผู้ใช้งานเข้าสู่ระบบไม่ได้

| สาเหตุที่เป็นไปได้ | วิธีตรวจสอบ/แก้ไข |
|---|---|
| จำรหัสผ่านผิด | แอดมินตั้งรหัสผ่านใหม่ให้ที่หน้าจัดการผู้ใช้งาน (บทที่ 12) |
| ชื่อผู้ใช้เพี้ยนจากการพิมพ์ตอนสร้างบัญชี (มีอักขระแปลกปลอมติดมา เช่น จากคีย์บอร์ดค้างโหมดภาษาไทย) | ตรวจสอบชื่อผู้ใช้จริงในหน้าจัดการผู้ใช้งานหรือ phpMyAdmin เทียบกับชื่อที่ผู้ใช้พิมพ์เข้าระบบ |
| บัญชีถูกระงับ (บล็อก) | ตรวจสอบสถานะที่หน้าจัดการผู้ใช้งาน แล้วกด "ปลดระงับ" ถ้าจำเป็น |

### ระบบตอบช้ามาก หรือไม่ตอบเลย

1. ตรวจสอบสถานะที่ **แผงควบคุมแอดมิน → ภาพรวม** ว่า CPU/RAM เต็มหรือไม่
2. ตรวจสอบสถานะการเชื่อมต่อ Ollama ว่าขึ้น `OK` หรือ `DOWN`
3. ถ้า CPU/RAM สูงมาก อาจเป็นเพราะมีคนใช้งานพร้อมกันหลายคนบนเครื่องที่ไม่มี GPU — พิจารณาเปลี่ยนโมเดลเริ่มต้นเป็นรุ่นที่เล็กลง (บทที่ 10)
4. ดูล็อกของ backend เพื่อหา error โดยละเอียด:
   ```bash
   docker compose logs -f backend
   ```

### เชื่อมต่อฐานข้อมูลไม่ได้ (สถานะขึ้น DOWN)

```bash
# ตรวจสอบว่า mysql ทำงานปกติหรือไม่
docker compose ps mysql

# ดูล็อกของ mysql
docker compose logs mysql

# ลองรีสตาร์ท
docker compose restart mysql backend
```

### พื้นที่ดิสก์เต็ม

โมเดล AI แต่ละตัวมีขนาดหลาย GB หากดาวน์โหลดไว้หลายตัวอาจใช้พื้นที่มาก ตรวจสอบพื้นที่คงเหลือได้ที่แดชบอร์ด (บทที่ 14) หากต้องการลบโมเดลที่ไม่ใช้แล้ว:

```bash
docker compose exec ollama ollama list      # ดูรายชื่อโมเดลที่ติดตั้งอยู่
docker compose exec ollama ollama rm <ชื่อโมเดล>
```

### ลืมรหัสผ่านของบัญชีแอดมินคนเดียวที่เหลืออยู่

เข้าถึงฐานข้อมูลโดยตรงผ่าน backend container เพื่อตั้งรหัสผ่านใหม่:

```bash
docker compose exec backend php -r "
require '/var/www/html/src/Config.php';
require '/var/www/html/src/Database.php';
\$pdo = Database::connection();
\$hash = password_hash('รหัสผ่านใหม่ที่ต้องการ', PASSWORD_BCRYPT);
\$pdo->prepare('UPDATE users SET password_hash = ? WHERE username = ?')->execute([\$hash, 'ชื่อผู้ใช้แอดมิน']);
echo 'เรียบร้อย' . PHP_EOL;
"
```

## 19.3 การอัปเดตระบบเป็นเวอร์ชันใหม่

```bash
git pull                          # ดึงโค้ดเวอร์ชันล่าสุด
docker compose up -d --build      # build และรันใหม่
```

ข้อมูลในฐานข้อมูลจะไม่หายไปเพราะเก็บแยกอยู่ใน Docker volume (`mysql_data`) ไม่ได้ถูกลบเมื่อ build ใหม่

## 19.4 คำสั่งตรวจสุขภาพระบบโดยรวม

```bash
docker compose ps                       # สถานะทุกบริการ
docker compose logs -f --tail=100       # ล็อกล่าสุดของทุกบริการ
curl -o /dev/null -s -w "%{http_code}\n" http://localhost:8095/api/health   # ตรวจสอบ backend/Ollama
```
