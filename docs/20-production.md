โครงสร้างที่ผ่านมาทั้ง 19 บทเป็น baseline ที่ใช้งานได้จริง แต่ก่อนเปิดให้คนในองค์กรใช้งานจริงในวงกว้าง ควรตรวจสอบรายการต่อไปนี้ให้ครบ

## 20.1 Checklist ก่อนใช้งานจริง

- [ ] เปลี่ยนรหัสผ่านฐานข้อมูลจากค่าเริ่มต้น (`DB_PASSWORD`, `DB_ROOT_PASSWORD` ใน `.env`) แล้ว
- [ ] ตั้งรหัสผ่านบัญชีแอดมินให้รัดกุม ไม่ใช่รหัสผ่านตัวอย่างที่เคยใช้ทดสอบ
- [ ] ทำ **HTTPS** ผ่าน reverse proxy ด้านหน้า (เช่น Caddy หรือ Traefik) หรือ Nginx + Let's Encrypt — จำเป็นเพื่อความปลอดภัยของรหัสผ่านและ session cookie เมื่อเข้าถึงผ่านอินเทอร์เน็ต
- [ ] จำกัดการเข้าถึง **phpMyAdmin (พอร์ต 8096)** ให้เฉพาะเครือข่ายภายในองค์กร/VPN เท่านั้น อย่าเปิดออกอินเทอร์เน็ตตรงๆ
- [ ] ตั้งค่า **โควตารายวัน** ให้เหมาะสมกับจำนวนผู้ใช้งานจริงและกำลังของเซิร์ฟเวอร์ (บทที่ 5, 12)
- [ ] ทดสอบขั้นตอน**สำรอง/กู้คืนข้อมูล**อย่างน้อย 1 รอบ (บทที่ 19)
- [ ] ปรับ system prompt ในไฟล์ `.env` (`APP_SYSTEM_PROMPT`) ให้เหมาะกับบริบทองค์กรจริง
- [ ] เตรียมเนื้อหาระบบความรู้ AI (RAG + Rule) สำหรับคำถามที่พบบ่อยที่สุดขององค์กรไว้ล่วงหน้า (บทที่ 16-17)

## 20.2 เกี่ยวกับการ mount ฮาร์ดแวร์ของโฮสต์

Container `backend` จะ mount `/proc` และ `/` ของเครื่องโฮสต์แบบ **read-only** เพื่อให้หน้าแดชบอร์ดอ่านค่า CPU/RAM/Disk ได้ (ไม่ใช่ privileged mode และเขียนอะไรกลับไปที่โฮสต์ไม่ได้) หากกังวลเรื่องสิทธิ์การเข้าถึง สามารถลบสอง mount นี้ออกจาก `docker-compose.yml` ได้ (หน้าแดชบอร์ดจะแสดง "-" แทนตัวเลข)

หากรันบนเครื่อง **Windows (Docker Desktop/WSL2)** ตัวเลขที่เห็นจะสะท้อนสภาพแวดล้อมที่ Docker รันอยู่จริง (WSL2 VM) ไม่ใช่ตัวเลขจาก Task Manager ของ Windows โดยตรง — เมื่อย้ายไปรันบน Linux เต็มรูปแบบ (เช่น Proxmox VM) ตัวเลขจะตรงกับโฮสต์จริงทั้งหมด

## 20.3 การขยายระบบให้รองรับผู้ใช้มากขึ้น

- **เพิ่ม RAM/CPU** ให้เซิร์ฟเวอร์ — ปัจจัยที่ส่งผลต่อความเร็วมากที่สุดเมื่อไม่มี GPU
- **พิจารณาใช้ GPU** หากงบประมาณเอื้ออำนวย จะช่วยให้ตอบเร็วขึ้นมากโดยเฉพาะเมื่อมีผู้ใช้พร้อมกันจำนวนมาก
- ฐานข้อมูล MySQL/MariaDB ที่ใช้อยู่ออกแบบมารองรับผู้ใช้ระดับ ~2,000 คนอยู่แล้วโดยไม่ต้องปรับแต่งเพิ่ม

## 20.4 แนวทางพัฒนาต่อ (สำหรับนักพัฒนา)

ฟีเจอร์ที่ยังไม่รองรับในเวอร์ชันปัจจุบันและเป็นแนวทางขยายในอนาคต:

| ฟีเจอร์ | เหตุผลที่ยังไม่ทำ |
|---|---|
| ค้นหาเว็บ / ค้นหาเชิงลึก | ต้องใช้ API ค้นหาภายนอกที่มีค่าใช้จ่าย (ขัดกับหลักการไม่พึ่งพา API ภายนอก) |
| แปลงเสียงเป็นข้อความจากไฟล์แนบ | ต้องเพิ่มบริการ Whisper แยกต่างหาก ใช้ RAM/CPU เพิ่ม |
| สร้างภาพ/วิดีโอใหม่ | ต้องใช้บริการแยก เช่น Stable Diffusion ซึ่งช้ามากบน CPU |
| เชื่อมต่อ GitHub / Canva | ต้องสมัคร API แยกต่างหากและมีค่าใช้จ่าย |

หากต้องการเพิ่มฟีเจอร์เหล่านี้ในอนาคต จุดเริ่มต้นที่ดีคือดูโครงสร้างเมนู "➕" ในหน้าแชท (บทที่ 8) ที่เตรียมช่องไว้ให้แล้ว รอเพียงเชื่อมต่อ backend logic เพิ่มเติม
