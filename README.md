# FAONEX.AI

เว็บแอป AI Chatbot สำหรับตอบคำถามภายในองค์กร ธีมมืด (dark) พร้อมโลโก้และตัวอักษรไล่สีม่วง-ขาวแบบมีประกาย (shimmer) ประกอบด้วย:

- **Frontend**: SvelteKit + Tailwind CSS (build เป็น static site แล้ว serve ผ่าน Nginx)
- **Backend**: PHP (Apache) เป็น REST API เชื่อมต่อกับ Ollama + **MySQL/MariaDB** (ผู้ใช้/ประวัติแชท) — เลือกใช้ MySQL/MariaDB แทน SQLite เพื่อรองรับผู้ใช้งานพร้อมกันจำนวนมาก (ออกแบบไว้รองรับได้ถึงระดับ ~2,000 คน)
- **AI**: [Ollama](https://ollama.com) รันโมเดลภาษาในเครื่อง ไม่ต้องใช้ API key ภายนอก มี 2 โหมด (แชททั่วไป / เขียนโค้ด)
- **Reverse proxy**: Nginx เสิร์ฟหน้าเว็บ + proxy คำขอ `/api/*` ไปยัง backend
- **phpMyAdmin**: จัดการฐานข้อมูลผ่านหน้าเว็บได้สะดวก (พอร์ต 8096) — เหมาะสำหรับครูผู้ดูแลระบบที่ไม่ถนัดคำสั่ง SQL

## ฟีเจอร์

- ธีมมืดทั้งระบบ โลโก้ FAONEX.AI พร้อมเอฟเฟกต์เรืองแสง (glow) และตัวอักษรแบรนด์ไล่สีม่วง-ขาวแบบมีประกาย
- **คำตอบแบบ streaming**: AI ตอบทีละคำแบบเรียลไทม์ (เหมือน ChatGPT/Claude) เริ่มเห็นคำตอบภายในเสี้ยววินาทีแทนที่จะรอคำตอบเต็มก่อนค่อยแสดง มีปุ่ม ⏹ หยุดตอบกลางคันได้ (คำตอบส่วนที่ตอบไปแล้วจะถูกบันทึกไว้)
- **ตอบได้ยาวแบบไม่จำกัด**: ปรับ context window และจำนวน token สูงสุดต่อคำตอบให้ไม่ถูกตัดกลางคัน ปรับค่าได้ที่ `.env` (`OLLAMA_NUM_CTX`, `OLLAMA_NUM_PREDICT`)
- **หน้าแชทออกแบบใหม่แบบ ChatGPT**: ไซด์บาร์เปิด/ปิดได้ (ปุ่ม ☰), ช่องค้นหาแชทในประวัติ, ปุ่ม "แชทใหม่" ขนาดกะทัดรัด, ปุ่ม ➕ ข้างช่องพิมพ์เปิดเมนูแนบไฟล์/ตัวเลือกอื่นๆ, ข้อความ AI แสดงแบบไม่มีกรอบพร้อมไอคอนคล้าย ChatGPT
- ระบบสมาชิก: สมัคร/เข้าสู่ระบบ (username + password, session-based)
- เก็บประวัติการแชทของแต่ละผู้ใช้แยกเป็นบทสนทนา (บันทึกถาวรในฐานข้อมูล) ดูย้อนหลัง/ค้นหา/ลบได้จากแถบด้านข้าง
- พิมพ์ข้อความด้วยเสียง (ปุ่มไมโครโฟน ใช้ Web Speech API ของเบราว์เซอร์) และให้บอทอ่านคำตอบออกเสียงได้ (ปุ่ม 🔊 ต่อข้อความ หรือเปิดออโต้ที่ header)
- โหมด "เขียนโค้ด" สลับไปใช้โมเดลเฉพาะทางด้านโปรแกรมมิ่ง (เช่น `qwen2.5-coder`) พร้อม render โค้ดเป็น code block พร้อมปุ่มคัดลอก
- **เลือกโมเดลแชทได้หลายค่าย** (Llama 3.2 / Qwen 2.5 / Gemma 2 / Mistral — ทั้งหมดเป็นโมเดล open-source ฟรี) จากดรอปดาวน์ที่ header โมเดลที่ยังไม่เคยใช้จะดาวน์โหลดอัตโนมัติตอนเลือกครั้งแรก
- **แนบไฟล์ในแชท**: แนบรูปภาพให้ AI ช่วยดู/อธิบาย (ใช้โมเดล vision แยกต่างหาก ดาวน์โหลดอัตโนมัติตอนแนบรูปครั้งแรก) หรือแนบไฟล์ข้อความ (.txt/.md/.csv) ให้ AI อ่านเนื้อหาประกอบคำตอบ
- แถบแสดงโควตาการใช้งานวันนี้ (จำนวนครั้ง/token เทียบกับลิมิต) ในไซด์บาร์ ผู้ใช้ทุกคนเห็นสถานะของตัวเองแบบเรียลไทม์
- **Dark/Light mode** และ **ภาษาไทย/อังกฤษ** สลับได้ทั้งเว็บจากเมนู ⚙️ ตั้งค่า (บันทึกค่าไว้ในเบราว์เซอร์ ไม่ต้องตั้งใหม่ทุกครั้ง)
- **แผงควบคุมแอดมิน** (`/admin`, เห็นเฉพาะบัญชีสิทธิ์แอดมิน — ปุ่ม 🛡 ที่ header):
  - จัดการผู้ใช้งาน: เพิ่ม/แก้ไข/ลบ/ระงับ(บล็อก)บัญชีแบบกดปุ่มเดียว, ตั้งสิทธิ์แอดมิน, ค้นหาผู้ใช้
  - นำเข้าผู้ใช้จากไฟล์ Excel (.xlsx) เป็นชุด, ส่งออกรายชื่อผู้ใช้ทั้งหมดเป็น Excel, ส่งออกรายงานผู้ใช้รายคนเป็น PDF (รองรับภาษาไทย)
  - จำกัดโควตารายวันต่อผู้ใช้ (จำนวนครั้งและจำนวน token) เพื่อประหยัดทรัพยากรระบบ ตั้งเฉพาะรายคนได้ ไม่งั้นใช้ค่าเริ่มต้นของระบบ
  - ประวัติข้อความที่ระบบตรวจจับว่าอาจเข้าข่ายอันตราย/ผิดกฎหมาย (heuristic keyword matching — ดูหัวข้อ "ข้อจำกัดของระบบตรวจจับ")
  - หน้าสรุปสถิติ: การ์ดตัวเลขรวม, **กราฟแท่ง** เปรียบเทียบคำขอ/token แบบรายวัน/เดือน/ปี, **กราฟวงกลม** สัดส่วนการใช้งานตามโหมด (แชท/โค้ด), ผู้ใช้ที่ใช้ token สูงสุด
  - มอนิเตอร์ฮาร์ดแวร์แบบเรียลไทม์ (โพลทุก 15 วินาที): % การใช้ CPU/RAM/พื้นที่ดิสก์, สถานะการเชื่อมต่อฐานข้อมูล/Ollama/Backend, สรุปจำนวนแถวในแต่ละตารางฐานข้อมูล พร้อมแบนเนอร์แจ้งเตือนเมื่อเกินเกณฑ์
  - จัดการ **API key** สำหรับให้เซิร์ฟเวอร์ภายนอกเรียกใช้ AI ผ่าน public API (ดูหัวข้อ "API สำหรับเซิร์ฟเวอร์ภายนอก")
  - **ความรู้ AI (RAG + Rule)**: กำหนด "หัวข้อ" ที่ต้องการควบคุมคำตอบ พิมพ์คำตอบเองได้ทันทีหรืออัปโหลดเอกสาร PDF อ้างอิง (ไม่บังคับ) พร้อมดาวน์โหลดฟอร์มตัวอย่างการเขียนคำตอบ (ดูหัวข้อ "ระบบความรู้ AI (RAG + Rule)")

## เริ่มใช้งาน

### 1. ข้อกำหนดเบื้องต้น

- ติดตั้ง Docker Desktop (รองรับ `docker compose`)
- แนะนำ RAM อย่างน้อย ~8GB ขึ้นไป (รันครั้งแรกมี 2 โมเดล: แชททั่วไป + เขียนโค้ด — โมเดลแชทตัวอื่น/โมเดล vision ดาวน์โหลดเพิ่มทีหลังตอนมีคนเลือกใช้ ยิ่งดาวน์โหลดหลายตัวยิ่งใช้พื้นที่ดิสก์มากขึ้น แต่ไม่ได้ใช้ RAM พร้อมกันทั้งหมดเพราะ Ollama โหลดแค่โมเดลที่กำลังใช้งาน)
- เครื่องนี้ไม่มี GPU จึงรันบน CPU ล้วน — คำตอบอาจใช้เวลาหลายวินาทีถึงเป็นนาทีต่อข้อความ ขึ้นกับสเปกเครื่อง

### 2. ตั้งค่า

ไฟล์ `.env` ถูกสร้างไว้ให้แล้วพร้อมค่าเริ่มต้น ปรับได้ตามต้องการ:

```env
OLLAMA_MODEL=llama3.2            # โมเดลสำหรับแชททั่วไป (ตัวเลือกเริ่มต้นในดรอปดาวน์)
OLLAMA_CODE_MODEL=qwen2.5-coder:3b  # โมเดลสำหรับโหมดเขียนโค้ด
OLLAMA_VISION_MODEL=llava-phi3   # โมเดลสำหรับดูรูปภาพที่แนบมา
APP_ORG_NAME=องค์กรของเรา          # ชื่อองค์กร แสดงบนหน้าเว็บ
OLLAMA_TIMEOUT=120                # timeout รอคำตอบ AI ปกติ (วินาที)

# โควตาเริ่มต้นต่อผู้ใช้ 1 คนต่อวัน (แอดมินตั้งค่าเฉพาะรายคนทับค่านี้ได้ในหน้าจัดการผู้ใช้ /admin/users)
# ใส่ 0 = ไม่จำกัด
APP_DEFAULT_DAILY_REQUEST_LIMIT=100
APP_DEFAULT_DAILY_TOKEN_LIMIT=20000

# ฐานข้อมูล MySQL/MariaDB — แก้รหัสผ่านเหล่านี้ก่อนใช้งานจริงเสมอ โดยเฉพาะถ้าเซิร์ฟเวอร์เข้าถึงได้จากภายนอก
DB_NAME=faonex
DB_USER=faonex
DB_PASSWORD=faonex_change_me
DB_ROOT_PASSWORD=faonex_root_change_me
```

โมเดลอื่นที่น่าสนใจ (ดูเพิ่มเติมที่ https://ollama.com/library):
- แชททั่วไป: `llama3.2` (เล็ก/เร็ว) หรือ `qwen2.5:7b` (คุณภาพภาษาไทยดีขึ้น แต่หนักขึ้น)
- เขียนโค้ด: `qwen2.5-coder:3b` (เบา เหมาะกับ CPU) หรือ `qwen2.5-coder:7b`/`14b` (แม่นยำขึ้นแต่ช้าลงมากถ้าไม่มี GPU)
- ดูรูปภาพ: `llava-phi3` (ค่าเริ่มต้น ทดสอบแล้วใช้งานได้ดีบน CPU) — **หมายเหตุ**: เคยลอง `moondream` แล้วพบว่าตอบกลับว่างเปล่าเสมอบน Ollama เวอร์ชันที่ทดสอบ (น่าจะเป็นบั๊กของโมเดลนั้นเอง) จึงเปลี่ยนมาใช้ `llava-phi3` แทน

ปุ่ม + ในหน้าจัดการผู้ใช้และดรอปดาวน์เลือกโมเดลในหน้าแชท ให้ผู้ใช้เลือกโมเดลแชทได้เอง (Llama 3.2 / Qwen 2.5 / Gemma 2 / Mistral) โดยไม่ต้องแก้ `.env` — โมเดลที่ยังไม่เคยดาวน์โหลดจะโหลดอัตโนมัติตอนเลือกใช้ครั้งแรก (อาจใช้เวลา 1-5 นาทีขึ้นกับขนาดและความเร็วเน็ต)

### 3. รันระบบ

```bash
docker compose up -d --build
```

รอบแรกที่รัน service `ollama-init` จะดาวน์โหลดโมเดลทั้งสองตัวอัตโนมัติ (รวมกันหลาย GB อาจใช้เวลาสักครู่) ตรวจสอบความคืบหน้าได้ด้วย:

```bash
docker compose logs -f ollama-init
```

เมื่อพร้อมแล้วเปิดเบราว์เซอร์ไปที่ `http://localhost:8095` แล้วสมัครสมาชิกเพื่อเริ่มใช้งาน (ระบบยังไม่มีบัญชีเริ่มต้นให้ ต้องสมัครเองครั้งแรก)

**บัญชีแรกที่สมัครในระบบ (เมื่อยังไม่มีผู้ใช้งานเลย) จะได้สิทธิ์แอดมินอัตโนมัติ** ถ้าจะให้บัญชีที่มีอยู่แล้วเป็นแอดมินแทน (เช่น กรณีเคยสมัครไว้ก่อนฟีเจอร์นี้จะมี) ให้แอดมินคนอื่นตั้งสิทธิ์ให้ผ่านหน้า `/admin/users` หรือรันคำสั่งนี้ครั้งเดียว (แทน `USERNAME` ด้วยชื่อผู้ใช้จริง):

```bash
docker compose exec backend php -r "
require '/var/www/html/src/Config.php';
require '/var/www/html/src/Database.php';
\$pdo = Database::connection();
\$pdo->prepare(\"UPDATE users SET role = 'admin' WHERE username = ?\")->execute(['USERNAME']);
"
```

### 4. เข้าใช้งาน phpMyAdmin

เปิดเบราว์เซอร์ไปที่ `http://localhost:8096` แล้วล็อกอินด้วยค่าที่ตั้งไว้ใน `.env` (server: `mysql` กรอกอัตโนมัติอยู่แล้ว, username/password: ตาม `DB_USER`/`DB_PASSWORD` หรือ `root`/`DB_ROOT_PASSWORD` สำหรับสิทธิ์เต็ม) ใช้สำหรับดู/แก้ไขข้อมูลในฐานข้อมูลโดยตรงผ่านหน้าเว็บ โดยไม่ต้องพิมพ์คำสั่ง SQL เอง

### 5. หยุดระบบ

```bash
docker compose down
```

ข้อมูลจะยังอยู่ใน volume แม้ปิดระบบ: `ollama_data` (โมเดลที่ดาวน์โหลด) และ `mysql_data` (ฐานข้อมูล MySQL/MariaDB — บัญชีผู้ใช้/ประวัติแชททั้งหมด) ครั้งต่อไปที่รันจะไม่ต้องดาวน์โหลด/สมัครใหม่

> **หมายเหตุการย้ายระบบ**: เวอร์ชันนี้เปลี่ยนฐานข้อมูลจาก SQLite มาเป็น MySQL/MariaDB ข้อมูลเดิมในไฟล์ SQLite (volume `backend_data` ของเวอร์ชันก่อนหน้า) **จะไม่ถูกย้ายมาให้อัตโนมัติ** ต้องสมัครสมาชิกใหม่ (บัญชีแรกที่สมัครจะได้สิทธิ์แอดมินอัตโนมัติเหมือนเดิม)

## API สำหรับเซิร์ฟเวอร์ภายนอก (public API)

นอกจาก `/api/*` ที่ใช้ session cookie (สำหรับหน้าเว็บ) ระบบมี public API แยกต่างหากที่ **เซิร์ฟเวอร์อื่น** เรียกใช้ได้โดยไม่ต้อง login ผ่านเบราว์เซอร์ ยืนยันตัวตนด้วย API key แทน:

1. แอดมินสร้าง API key ได้ที่หน้า `/admin/api-keys` (คัดลอก key ตอนสร้างทันที เพราะจะไม่แสดงให้เห็นอีก)
2. เรียกใช้จากเซิร์ฟเวอร์อื่นด้วย `Authorization: Bearer <key>`:

```bash
curl -X POST https://<โดเมนหรือไอพีของคุณ>:8095/api/v1/chat \
  -H "Authorization: Bearer fao_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"message": "สวัสดี", "mode": "chat"}'
```

| Method | Path             | คำอธิบาย                                                                 |
|--------|------------------|---------------------------------------------------------------------------|
| POST   | `/api/v1/chat`   | `{ message, history?: [{role, content}], mode?: "chat"\|"code", model?, images?: [base64,...] }` คืนค่า `{ reply, promptTokens, completionTokens }` |
| GET    | `/api/v1/models` | รายชื่อโมเดลแชทที่เลือกได้ พร้อมสถานะติดตั้ง                              |

หมายเหตุ:
- `/api/v1/*` เป็น **stateless** (ไม่บันทึกประวัติบทสนทนาให้) ผู้เรียกต้องส่ง `history` เองถ้าต้องการบริบทหลายรอบ ต่างจาก `/api/chat` ที่ใช้ในหน้าเว็บซึ่งเก็บประวัติให้อัตโนมัติ
- มีโควตารายวันร่วมกันทุก API key (ใช้ค่า `APP_DEFAULT_DAILY_REQUEST_LIMIT` / `APP_DEFAULT_DAILY_TOKEN_LIMIT` เดียวกับผู้ใช้ทั่วไป) เกินแล้วจะได้ 429
- เปิด CORS (`Access-Control-Allow-Origin: *`) เฉพาะเส้นทาง `/v1/*` เท่านั้น เส้นทางอื่นยังคงจำกัดแบบ same-origin ตามปกติ

## ระบบความรู้ AI (RAG + Rule)

ให้แอดมินกำหนดได้ว่า "ถ้าถามเรื่องนี้ ให้ AI ตอบจากเอกสารนี้เท่านั้น" — ใช้ที่หน้า `/admin/knowledge`

**หลักการทำงาน**:

1. **Rule (คำค้น)** — แอดมินสร้าง "หัวข้อ" พร้อมคำค้น เช่น หัวข้อ "การสมัครเรียน" คำค้น `สมัครเรียน, รับสมัคร, ใบสมัคร, enrollment` เมื่อผู้ใช้พิมพ์คำถามที่มีคำเหล่านี้ ระบบจะจับคู่กับหัวข้อนั้นโดยอัตโนมัติ (ถ้าคำถามตรงกับหลายหัวข้อ จะเลือกหัวข้อที่มีคำตรงมากที่สุด)
2. **RAG (เนื้อหาอ้างอิง)** — ใส่เนื้อหาให้แต่ละหัวข้อได้ 2 ทาง ใช้ร่วมกันได้ในหัวข้อเดียวกัน:
   - **พิมพ์คำตอบเอง** ในหน้า "จัดการเนื้อหา" ของหัวข้อนั้น ได้ทันทีโดยไม่ต้องมีไฟล์ PDF
   - **อัปโหลดไฟล์ PDF** อ้างอิง (ไม่บังคับ อัปโหลดได้หลายไฟล์ต่อหัวข้อ) ถ้ามีจะเป็นข้อมูลเพิ่มเติมให้ AI ใช้ตอบ

   ไม่ว่าจะพิมพ์เองหรืออัปโหลด PDF ระบบจะแบ่งเนื้อหาเป็นส่วนย่อย (chunk) แล้วแปลงแต่ละส่วนเป็นเวกเตอร์ (embedding) ด้วยโมเดล Ollama (`nomic-embed-text` ค่าเริ่มต้น) เก็บไว้ในฐานข้อมูลเหมือนกัน
3. เมื่อคำถามตรงกับหัวข้อไหน ระบบจะแปลงคำถามเป็นเวกเตอร์เช่นกัน แล้วค้นหาส่วนเนื้อหาที่ใกล้เคียงที่สุด (cosine similarity) จากเนื้อหาทั้งหมดในหัวข้อนั้น (ทั้งที่พิมพ์เองและจาก PDF) แล้วบังคับให้ AI ตอบโดยอ้างอิงจากเนื้อหาที่ค้นเจอ **เท่านั้น** ห้ามใช้ความรู้อื่นนอกเหนือจากนี้
4. **ถ้าไม่พบข้อมูลที่เกี่ยวข้องเลย** (หัวข้อยังไม่มีเนื้อหา หรือค้นแล้วไม่พบส่วนที่ใกล้เคียงพอ) ระบบจะตอบด้วย "ข้อความสำรอง" ที่แอดมินตั้งไว้ทันที (เช่น "ขออภัย ไม่พบข้อมูลเรื่องนี้ กรุณาติดต่อฝ่ายทะเบียนโดยตรง") โดยไม่เรียกใช้ AI เลย ประหยัดทรัพยากรและไม่นับโควตา token
5. **คำถามที่ไม่ตรงกับหัวข้อใดเลย** จะได้รับคำตอบจาก AI ตามปกติเหมือนไม่มีระบบนี้อยู่ (ไม่ถูกจำกัด)

**กำหนดคำตอบได้หลายประเภท**: สร้างหัวข้อได้ไม่จำกัดจำนวน แต่ละหัวข้อมีคำค้น เนื้อหา และข้อความสำรองเป็นของตัวเอง เหมาะกับกรณีมีหลายเรื่องที่ต้องการควบคุมคำตอบแยกกัน (เช่น การสมัครเรียน, ทุนการศึกษา, ตารางเรียน ฯลฯ)

**ฟอร์มตัวอย่างการเขียนคำตอบ**: ปุ่ม "⬇ ดาวน์โหลดฟอร์มตัวอย่าง (Word)" ที่หน้า `/admin/knowledge` ดาวน์โหลดไฟล์ .docx ที่มีคำแนะนำและตัวอย่างการเขียนคำตอบที่ดี ใช้เตรียมเนื้อหาก่อนพิมพ์ลงระบบโดยตรง หรือก่อนบันทึกเป็น PDF เพื่ออัปโหลดภายหลังก็ได้

**หมายเหตุ**:
- โมเดล embedding (`OLLAMA_EMBED_MODEL` ใน `.env`, ค่าเริ่มต้น `nomic-embed-text`) จะถูกดาวน์โหลดอัตโนมัติตอนบันทึกเนื้อหา/ถามคำถามที่ตรงหัวข้อเป็นครั้งแรก (คล้ายโมเดลแชท/vision อื่นๆ ในระบบ)
- ไฟล์ PDF ที่อัปโหลดต้องมีข้อความจริง (ไม่ใช่ไฟล์สแกนภาพล้วนที่ไม่มีเลเยอร์ข้อความ)
- ปรับความเข้มงวดในการค้นหาได้ผ่าน `.env`: `APP_RAG_TOP_K` (จำนวนส่วนเนื้อหาสูงสุดที่ดึงมาอ้างอิง ค่าเริ่มต้น 4) และ `APP_RAG_SIMILARITY_THRESHOLD` (ค่าความใกล้เคียงขั้นต่ำ ค่าเริ่มต้น 0.35 — ตั้งสูงขึ้นถ้าต้องการให้เข้มงวดขึ้น)

## ข้อจำกัดของระบบตรวจจับข้อความอันตราย

การตรวจจับใช้วิธี **เช็คคำต้องห้ามแบบ heuristic** (string matching ในไฟล์ `backend/src/Config.php` ฟังก์ชัน `dangerousKeywords()`) เพื่อความรวดเร็วและไม่เพิ่มภาระการประมวลผล AI (ไม่ได้ส่งข้อความไปให้โมเดลอื่นตรวจซ้ำ) ข้อดีคือเร็วและประหยัดทรัพยากร แต่ข้อจำกัดคือ:

- **ตรวจพลาดได้** หากผู้ใช้เลี่ยงคำ สะกดผิดตั้งใจ หรือใช้ภาษาอื่นที่ไม่อยู่ในลิสต์
- **แจ้งเตือนผิด (false positive) ได้** เช่น คำถามเชิงวิชาการ/ประวัติศาสตร์ที่บังเอิญมีคำในลิสต์
- ระบบ**ไม่บล็อก**ข้อความที่ตรวจพบ เพียงบันทึกไว้ให้แอดมินตรวจสอบที่ `/admin/flags` เท่านั้น (กันไม่ให้บล็อกผิดจนรบกวนการใช้งานจริง)

แก้ไข/เพิ่มคำในลิสต์ได้ที่ `backend/src/Config.php::dangerousKeywords()` แล้ว build backend ใหม่

| 🖼️ รูปภาพ (ให้ AI **ดู/อธิบาย**) | ✅ รองรับ | กดปุ่ม 📎 แนบรูปได้เลย ใช้โมเดล vision (`llava-phi3` ค่าเริ่มต้น) แยกจากโมเดลแชท/โค้ด — **ไม่เก็บรูปไว้ในประวัติแชท** (ประวัติจะโชว์แค่ข้อความ + เครื่องหมาย `[แนบรูปภาพ]`) |

## หมายเหตุสำหรับใช้งานจริง (production)

โครงสร้างนี้เป็น baseline ที่ใช้งานได้จริง แต่ก่อนนำไปใช้งานจริงในวงกว้าง ควรพิจารณาเพิ่มเติม:

- ทำ HTTPS ผ่าน reverse proxy ด้านหน้า (เช่น Caddy/Traefik) หรือ Nginx + certbot — จำเป็นเพื่อความปลอดภัยของรหัสผ่านและ session cookie เมื่อเข้าถึงผ่านอินเทอร์เน็ต
- จำกัดอัตราการเรียก (rate limiting) ที่ endpoint `/api/chat` และ `/api/auth/*` (กันสแปม/brute-force)
- สำรองข้อมูล (backup) volume `mysql_data` เป็นระยะ เนื่องจากเก็บบัญชีผู้ใช้และประวัติแชททั้งหมด — ทำได้ง่ายๆ ผ่านฟีเจอร์ Export ในหน้า phpMyAdmin (พอร์ต 8096) หรือคำสั่ง `docker compose exec mysql mariadb-dump -u root -p faonex > backup.sql`
- จำกัดการเข้าถึง phpMyAdmin (พอร์ต 8096) เฉพาะเครือข่ายภายในองค์กร/VPN เท่านั้น อย่าเปิดออกอินเทอร์เน็ตตรงๆ เพราะเป็นช่องทางเข้าถึงข้อมูลทั้งหมดในระบบ
- ปรับ system prompt ในไฟล์ `backend/src/Config.php` (หรือกำหนด `APP_SYSTEM_PROMPT` / `APP_CODE_SYSTEM_PROMPT` ใน `.env`) ให้เหมาะกับข้อมูลและบริบทองค์กร
- หากต้องการให้ AI ตอบจากข้อมูลภายในองค์กร (เอกสาร นโยบาย ฯลฯ) จะต้องเพิ่มระบบ RAG (ค้นคืนเอกสารมาแนบใน prompt) ซึ่งยังไม่รวมอยู่ใน baseline นี้
- container `backend` mount `/proc` และ `/` ของโฮสต์แบบ **read-only** เข้ามา (ดู `docker-compose.yml`) เพื่อให้หน้า Dashboard อ่าน CPU/RAM/Disk ของโฮสต์ได้ ไม่ใช่ privileged mode และเขียนอะไรกลับไปที่โฮสต์ไม่ได้ แต่ถ้ากังวลเรื่องสิทธิ์การเข้าถึง สามารถลบสอง mount นี้ออกได้ (หน้า Dashboard จะแสดง "-" แทนตัวเลขแทน)
- บนเครื่อง Windows (Docker Desktop/WSL2) ตัวเลข CPU/RAM/Disk ที่เห็นจะสะท้อนสภาพแวดล้อมที่ Docker รันอยู่จริง (WSL2 VM) ไม่ใช่ตัวเลขจาก Task Manager ของ Windows โดยตรง — เมื่อย้ายไปรันบน Linux VM (เช่น Proxmox) ตัวเลขจะตรงกับโฮสต์จริงทั้งหมด
